# Telekine 品牌提案 · 第二版

日期：2026-10-10。状态：品牌探索已获推进授权；检索发现同名技术项目和公司登记别名，Telekine 仍为候选。正式改名、数字资产采购与对外发布尚待验证。

## 定位与主文案

**Telekine：面向内网与生产环境的 AI 运维控制面。**

> 大脑留在中心，机器只管执行。
>
> 模型密钥集中管理，机器无需开放入站端口；断线先对账，未知不重跑。

英文品牌文案：The mind stays home. Only the hands go out.

英文产品说明：An AI operations control plane for private networks and production environments.

模型调用和 Agent 规划集中在主节点，机器上的执行端负责连接、执行、取消和对账。机器需要能访问主节点，无需直接访问模型服务。执行状态无法证明时挂起等待核对，避免盲目重试。

核心承诺按以下顺序呈现：

1. **未知不重跑。** 断线后先核对执行状态，无法证明时挂起等待人工核对。
2. **模型密钥集中管理。** 执行机器不保存模型密钥；设备身份和设备凭据仍保存在机器上。
3. **生产机无需访问公网。** 执行端主动连接可达的内网主节点，无需为执行端开放入站端口。

架构依据见 [架构方案](../architecture.md)，接入依据见 [机器接入](../worker-onboarding.md)。本文不替代运行和验收文档。

## 术语收敛

品牌名采用 Telekine 方向，WorkerPlane 暂作为仓库和内部工程名称。Core、Anchor 用于产品概念说明；首次出现同时给出“主节点”“执行端”。其余术语优先采用运维通用名称。

| 概念 | 建议显示名称 | 处理 |
| --- | --- | --- |
| 主节点服务 | Core（主节点） | 保留品牌名词 |
| Rust worker | Anchor（执行端） | 保留品牌名词 |
| Main Agent | 主 Agent | 不使用 Mind／主念 |
| WSS 连接 | 连接 | 不使用 Tether／念线 |
| 委派子任务 | 子任务 | 不使用 Reach／延伸 |
| 心跳 | 心跳 | 不使用 Pulse |
| connection epoch | 连接代次 | 技术诊断中使用，不使用 Grip |
| 执行状态无法证明 | 挂起待核对（Hold） | 状态文案说明原因和下一步 |
| 执行账本／事件记录 | 执行记录／审计轨迹 | 不引入 Trail 命令 |
| Job | 任务／执行 | 按当前产品上下文使用，不进行机械替换 |
| Session／Workspace | 会话／工作目录 | 保留现有模型边界 |
| Reconcile／Abort／Freeze | 对账／中止／冻结调度 | 保留通用操作 |

CLI、包名、服务名和配置路径保持现有实现；正式迁移方案确定后再统一修改。文案不能展示尚不存在的 `telekine` 命令作为可执行安装指南。

## 措辞边界

| 原措辞 | 第二版措辞 | 原因 |
| --- | --- | --- |
| 机器零出网 | 生产机无需访问公网 | 执行端仍需主动连接主节点 |
| 不开端口 | 无需开放入站端口 | 明确针对执行机器 |
| 不放密钥 | 机器不存模型密钥 | 设备仍有私钥和凭据 |
| 断线不重复执行 | 断线先对账，未知不重跑 | 表达系统处理原则，避免扩展为所有外部副作用的保证 |
| 零配置 | 无需手写配置文件、无需手动复制接入凭据 | 管理员批准和私有 CA 设置仍可能需要操作 |

不宣传“开机即用”“四平台均已验收”或“任意跨网络连接”。原提案中的用户级服务、平台覆盖和跨 NAT 限制应在发布前依据当前实现重新核验。

## Logo 打样

优先方向为 **A2 光标 T**：悬浮横梁表达远程施力，竖杆借用终端光标。对照方向为 A 悬浮 T 和 A3 悬浮提示符。

查看 [三方向 SVG 对照稿](telekine-logo-study.svg)。这是几何概念稿，不是正式 Logo；紫色为暂定强调色。

已渲染检查：三个方向在深浅背景和单色下均能保留轮廓。A2 的 16px 悬浮间隙可见、结构最简洁；A 的底部横脚更像大写 I；A3 更直接表达终端，但类似通用提示符。推荐继续打磨 A2，不能据此声称用户已识别出运维场景。目标用户测试尚未进行。

验证方式：比较 16px、32px、64px、单色、深浅背景，确认悬浮缝隙可见、轮廓可识别；请目标用户判断是否联想到终端或运维。正式稿再处理字形、间距、favicon 和品牌组合。

## 命名与数字资产

Telekine 的远程施力意象与集中规划、远程执行的架构一致。风险在于首次读音和听写不明确。

读音工作候选为 TEL-uh-kyne，尚未定案。用目标用户做双向测试：看名称读出、听名称拼写，记录读音分歧和误拼，不以团队熟悉度代替结果。

**[未核实]** 原提案中的 USPTO／WIPO 检索结论、相似商标风险评级、域名和包名可用性未经本轮独立核验，不作为可注册或可使用的结论。正式采用前核验中国及目标市场相关类别，并获取专业商标意见。

主域名暂不决定；核验可用性、采购成本及续费成本后再比较 `.dev` 和 `.ai`。

### 目标用户验证脚本

招募 5–8 位未看过提案的运维或基础设施工程师，分别记录原始答案；这是定性筛查，不是统计结论。

1. 只展示 Telekine，询问如何读、猜测是什么产品。
2. 对另一组只念候选读音，请其拼写；避免先展示文字造成提示。
3. 展示三个无名称 Logo 的 16px／32px 图，请描述联想和区分度，不提示“终端”或“念动力”。
4. 展示产品说明，请复述机器是否需要公网、是否存模型密钥、断线后怎么处理。
5. 记录误拼、读音分歧、场景误判和承诺误解；若多数回答持续偏离，再调整名称或文案。测试结果为空，不能用团队或 AI 判断冒充用户反馈。
