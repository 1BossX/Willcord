# Willcord 一页商业计划书

> 版本：2026-10-14 · 产品现状 v0.1.0-beta.4 · Apache-2.0 自托管 · 仓库 github.com/BossOptional/Willcord
> 说明：文中所有价格、目标、转化数字均为 **假设/待验证**；不含任何市场规模、收入或用户数估算。

## 一句话定位
**Willcord 是服务器上的「AI 执行边界层 / 控制面」**：不管上层是哪个 AI agent，落到 Linux+Docker 机器上的每个动作都经它**受限、审批、记账、可对账**——大脑留在中心，机器只管执行。我们不做“又一个 agent”。

**战略主线：A 做楔子，B 做架构。** **B（横向基础设施）**：只做策略 + 账本 + 中继，成为任何 agent 的执行边界层，天花板最高（目标是“agent 执行界的 Tailscale”），但依赖他人 agent 生态、变现路径更长——因此底层按 B 重建：worker 变成通用受控执行后端，自建 agent loop 降为可选。**A（垂直场景）**：顶层只打一个场景（交易机器人运维 / 告警诊断），拿下前 10 个真实用户。

## 问题
- 小团队想让 AI 帮忙排障，但不敢把模型密钥、SSH 和 root 交给一个“自己会跑”的 agent。
- 远程执行最怕的不是答错，而是**断线/重启后不知道命令跑没跑**，盲目重试会二次事故（重复下单、重复删数据、重复重启）。
- 现有方案二选一：要么全手工值守，要么给 agent 全权限；中间缺一层“可证明、可审批、可撤销”的执行边界。

## 方案与差异化
- **架构**：模型调用/会话/调度集中在主节点；worker 只出站 WSS、不开入站端口；**密钥永不下发 worker**。
- **品牌点：断线先对账，未知不重跑**。执行账本记录每次调用，重连先核对，无法证明状态的调用挂起待人工处置；四类故障（断线、主节点重启、取消、结果丢失）不盲重试（#81）。
- **诊断模式**：只读白名单在 worker 端强制；“诊断 → 批准具体动作（绑定机器/目标/参数）→ 执行 → 验证”开发中（#83）。
- **运维完整度**：安装器 SHA-256、CA 指纹接入、设备批准/撤销、在线备份恢复、升级前快照、token 轮换、取消/超时/预算。
- **诚实边界**：不是 shell 沙箱（需最小权限账户）；单管理员；内容会进入模型上下文；尚无跨 NAT 中继。
- 护城河不在 agent 循环（read/write/bash 自建 loop 最弱），而在**账本 + 策略 + 审批 + 中继**——这正是按 B 重建的部分。

## 目标客户与楔子
- **楔子：做市/量化小团队**——几台 VPS 跑机器人，怕误操作、夜里需要有人盯；创始人在交易圈有直接触达。
- 扩展：自建 Linux+Docker 服务的独立开发者与小团队（单管理员、自带模型 key）。
- 暂不追：需要 RBAC/审计合规的企业（多用户未交付）。

## 商业模式（假设/待验证）
- **开源核心免费（Apache-2.0）**：主节点、worker、执行账本、诊断模式，自托管。
- **最轻的收费点（假设）：托管主节点 = 中继 + 控制台**。用户只装 worker，顺带解决跨 NAT 与 Compose+CA 过重的问题。
- **增值（假设）**：策略层、审批通知、告警接入。**企业版预留**：RBAC / SSO / 审计导出（多用户交付后再谈）。
- 价位 **待验证**：O3 对 ≥5 位活跃用户报价，≥2 位付费即视为成立。

## 获客路径
1. **交易圈直推**：一对一陪装，首批试用来源。
2. **英文 README + 90 秒 demo GIF**：解决“0 star、仅中文文档、无演示”的零分发问题；统一文档中的版本号。
3. **MCP 生态分发**：worker 暴露为 MCP server，让 Claude Code / Codex / 任意 agent 直接调用，借其分发。

## 关键指标（6 周 OKR，10/12–11/22，均为待验证目标）
- **O1 首次价值**：5 位外部用户中 ≥4 位在 20 分钟内独立完成首次诊断；20 个故障用例 ≥16 个定位成功。
- **O2 受控执行**：诊断模式拦截全部越权；≥10 次受控验收；四类故障 0 次盲重试。
- **O3 需求与付费**：10 位试用 ≥6 位接入真实服务器；2 周内 ≥4 位跨日复用、≥3 位确认节省 15 分钟以上；报价 ≥5 位，≥2 位付费。

## 风险与取舍
- **风险**：零分发；定位夹在中间（企业缺 RBAC、个人嫌 Compose+CA 重）；B 依赖他人 agent 生态、变现慢；无跨 NAT 时“无入站端口”优势打折；文档版本号混乱损害信任。
- **不做**：多用户/RBAC（留给企业版）、通用编码 agent、多运行时、插件市场、自主修复、自建中继网络。
- **取舍**：只做 Linux+Docker、单管理员、自带模型 key；投入优先给“执行边界层”，agent 能力不追。
