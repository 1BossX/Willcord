# Worker Plane MVP 开发阶段与验收标准

日期：2026-10-06  
依据：[最终技术方案](worker-plane-mvp-architecture-final.md)与 Worker Plane MVP Spec v2  
选型：TypeScript 主节点、Pi SDK、Rust worker、React UI、SQLite WAL

## 执行规则

阶段按 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 推进。后续阶段可以提前准备类型、界面和文档，但不能把前置验收未通过的实现当作可靠依赖。

每阶段交付代码、操作说明和验收记录。记录包括版本、平台、场景、预期、实际结果以及必要的 job/call 标识。自动化验证可使用脚本化模型；涉及 Pi 能力时必须使用实际 SDK，涉及执行安全时必须使用真实 SQLite 和子进程。

所有阶段当前均为“未实施、未验收”。本文件定义标准，不代表已通过检查。P2 的演示闭环仅在受控环境验证，完成 P3/P4 前不作为可发布版本。

## 阶段总览

| 阶段 | 交付目标 | 通过后具备的能力 |
|---|---|---|
| P0 | Pi runtime spike | 确认 SDK 能满足受控执行与历史恢复 |
| P1 | 工程、协议、存储与身份 | 主节点和 worker 安全连接并识别固定目标 |
| P2 | 单 worker 执行闭环 | 固定会话经过队列执行远程工具并展示结果 |
| P3 | 去重、对账与重启恢复 | 故障不自动重复副作用，不确定执行阻塞 |
| P4 | 取消、预算、输出与人工处置 | 可停止任务、限制资源并处理不确定状态 |
| P5 | Main Agent 与委派 | 多机器任务经同一调度器协调和持久等待 |
| P6 | UI 与完整端到端体验 | 会话、队列、委派和恢复状态正确可见 |
| P7 | 双平台发布与全量验收 | Linux/macOS 部署可复现，MVP 可发布 |

## P0：PiRuntime spike

交付物：最小 Pi Adapter、能力验证程序、规范化模型历史与 checkpoint 格式、固定 SDK 版本、spike 结论。

当前 spike 结果见 [P0 PiRuntime Spike 结果](../spikes/pi-runtime/RESULTS.md)。Pi SDK 1.0.4 的受控工具、执行前完整批次 hook、SessionManager transcript 重开、faux provider abort、host 预算 gate 均已验证；P0 阶段整体仍进行中。

开发范围：替换工具执行、关闭本地工具、捕获完整模型轮次、恢复历史、取消请求、步数/token 限制和草稿事件。使用无实际外部副作用的测试工具。

验收标准：

1. Main 配置只能调用 list_workers/delegate/get_job；worker 配置只能调用远程 read/write/bash。不存在可调用的本地 shell/fs 或隐藏执行路径。
2. 模型产生工具调用时，在持久化授权前测试工具没有执行；同一轮多个工具可完整捕获并串行处理。
3. 从数据库历史重建 Pi 执行，保留原始工具 ID、参数、结果和消息关联。
4. 完整轮次提交后中断，恢复使用已有工具意图；未提交轮次中断可以重试，不执行旧草稿中的工具。
5. 取消推理后即使晚到模型响应，运行代次校验阻止新工具与终态提交。
6. 最大步数和 token 预算实际生效；不依靠提示词限制。
7. 父任务可结束当前 runtime 执行并持久等待，恢复后接受子任务结果，不保持模型轮询。
8. 取消导致工具未执行的历史可重新加载；自动压缩关闭，或压缩 checkpoint 已证明可恢复。

出口：全部通过才进入实际 Pi 集成。失败时记录具体能力缺口；不得自行替换 runtime 或降低语义。

## P1：工程、协议、存储与身份

交付物：单仓库、构建/检查命令、数据库 migrations、JSON Schema 与 TS/Rust 类型、主节点认证、worker 注册和本地配置。

开发范围：Fastify、SQLite WAL、Rust 数据目录锁、TLS 开发入口、token、worker 注册/心跳/epoch、workspace 映射。此阶段不执行模型生成的命令。

验收标准：

1. 从干净环境按文档构建主节点、UI 和 Rust worker；数据库从空库迁移成功，已有版本升级路径可验证。
2. 未登录用户不能提交任务、取消、读取历史/日志或订阅事件；变更请求拒绝无效 CSRF/Origin。
3. 无效、撤销或绑定其他 worker_id 的 token 无法注册；撤销关闭已有连接。
4. token 校验值与模型密钥存储符合方案，结构化日志不打印秘密。
5. worker_id 稳定、boot_id 每次启动变化、ledger_id 重启保持；重复启动共享数据目录被拒绝。
6. 未知协议版本、非法 Schema、超大帧被拒绝；两端规范化请求 hash 固定样例一致。
7. 心跳 10 秒、30 秒未收到判离线，明确断开立即离线；新连接获得更高 epoch，先对账才能调度。
8. SSH/HTTPS remote 对应同一 repo_id；多 workspace 必须显式选择；默认 workspace 显式配置。

出口：两个受控 worker 可注册和展示状态，未经认证不能产生业务执行。

## P2：单 worker 指定机器执行闭环

交付物：ExecutionCoordinator、worker_slots、消息幂等、基础 WorkerExecutor、read/write/bash、基本聊天与任务列表。

开发范围：固定目标 session、每机 FIFO、模型轮次提交、基本工具账本与结果 ACK、基础日志。账本持久化从第一版执行就存在，完整故障验证留给 P3。

验收标准：

1. 创建 worker session 必须指定 worker/workspace；不存在或明确 repo 不匹配时拒绝，不自动换目标。
2. 同 client_request_id 重试返回同 job；相同 ID 不同内容返回冲突。
3. 多个 session 同时提交，按机器 FIFO 执行；数据库和真实进程观测均证明最多一个活动 job。
4. 同一 session 消息按提交顺序使用历史，排队期间不提前调用模型。
5. read/write/bash 仅经 Coordinator 执行，执行请求先落库，结果和工具消息落库后才继续推理。
6. read 有界、拒绝二进制；write 原子替换，expected_hash 不匹配拒绝；路径越界被拒绝。
7. bash 使用固定 cwd/shell/env、关闭 stdin、无 PTY；非零退出码为 completed，不伪造为工具启动失败。
8. 同轮多个工具串行，日志中无第二个工具提前执行。
9. 离线允许提交并显示等待上线；上线对账后按顺序执行，24 小时等待期限可配置。
10. 完成“读取文件 → 修改文件 → 运行校验 → 返回摘要”的真实闭环，其他 workspace 未被误选。

出口：指定机器功能可演示。尚未证明所有故障语义，不进入正式发布。

## P3：去重、对账与重启恢复

交付物：完整执行账本、确认下界与 tombstone、reconcile、checkpoint 恢复、worker blocked、可控断线和崩溃验证程序。

使用“向文件追加唯一标记”等真实副作用作为判据，不能只检查消息发送次数。

验收标准：

| 故障或竞争 | 必须观察到的结果 |
|---|---|
| tool_call / accepted ACK 丢失 | 重连查询账本，已经接受的调用不重启 |
| 命令完成、tool_result 丢失 | 缓存结果重传，副作用只发生一次 |
| 主节点结果提交、result_ack 丢失 | 工具消息不重复，ACK 可以重发 |
| 相同 call_id 不同参数 | 返回冲突，无额外执行 |
| 清理详细结果后收到旧调用 | 下界/tombstone 拒绝执行 |
| worker 未重启、网络断开 | 命令继续，主节点保留槽且不派发下一工具 |
| accepted/running 与进程启动窗口崩溃 | 无法证明执行情况时 needs_attention，不重跑 |
| worker 完成结果落库后重启 | 返回原结果，不要求再次执行 |
| ledger 丢失或 ledger_id 改变 | worker 阻塞，不以记录不存在证明未执行 |
| 主节点派发前、后、结果落库后重启 | 从原请求/checkpoint 恢复，不重复生成或执行 |
| 新旧连接竞争 | 旧连接不接收新调用；已接受调用仍需对账 |
| workspace 配置版本变化 | 在途 job 不改绑；后续任务不静默切换目录 |

补充验收：重复帧不使终态倒退；过期推理不提交结果；对账未完成不可派发；等待期限不释放状态不明的执行槽；主节点第二实例启动被拒绝。

出口：全部故障场景达到预期，特别是无法证明时选择阻塞。发现重复副作用必须修复后重验相关场景。

## P4：取消、预算、输出与人工处置

交付物：取消全链路、进程组控制、任务与根预算、受限日志补读、磁盘清理、人工处置接口和基础 UI。

验收标准：

1. queued 取消原子结束且无工具；推理取消后不产生新调用。
2. 命令取消/超时执行 TERM → 宽限 → KILL → 等待退出；确认停止前不启动下一 job。
3. 离线执行取消保留请求与槽，重连优先对账/取消；cancel_ack 不被当作停止证明。
4. 完成与取消竞争保留真实结果，禁止后续调用；重复取消幂等，终态返回原状态。
5. 无法识别或停止残留执行时 unknown → needs_attention；不按陈旧 PID 误杀无关进程。
6. 人工“放弃任务”不解除 worker blocked；解除阻塞保存核对依据；新建重试使用新 ID。
7. 工具次数、token、运行时限实际限制执行，重启不重置；默认工具超时 600 秒、本地上限 1800 秒不可绕过。
8. stdout/stderr 带 stream/seq，可去重、重连补读；超过模型每流 64 KiB 和调用日志总计 10 MiB 明确截断。
9. 队列满和大输出不堵塞子进程管道；日志缺口明确可见，主节点也有容量限额。
10. 磁盘不足拒绝新调用，不删除未确认记录；日志过期返回明确状态，结果 ACK 不错误删除仍需补读的日志。
11. 超出总时限停止新调用，在途执行按取消处理；终止不明仍阻塞。

出口：可安全停止、限制与核对任务，所有不确定状态都能明确展示和处置。

## P5：Main Agent 与持久化委派

交付物：Main 工具、独立子 session、父子关系、delegation_id、等待集合、前置依赖、根预算、父取消。

验收标准：

1. delegate 原子创建子 session/job；重复 ID 返回原任务，不同内容冲突。
2. 父任务与 delegation ID 由服务端注入，模型不能伪造其他父任务。
3. 用户任务和委派进入同一 worker FIFO，仍最多一个活动 job。
4. 子任务等待期间无持续模型调用；父 job 不占 worker 槽。
5. 子任务完成事件丢失或主节点重启，数据库扫描仍恢复父等待；恢复不重复委派。
6. “机器 A 测试成功 → 机器 B 写说明”成功时按顺序执行；测试失败、取消或 needs_attention 时 B 不启动。
7. 前置依赖合法、无循环；未满足依赖不占 worker 队列位置，满足后才获得 FIFO 序号。
8. 子 session 与用户默认 session 隔离，可独立追问且目标固定，文件不自动跨机器传输。
9. 父任务取消传播到未终态子任务；子执行不明时父任务不宣称安全取消。
10. 父子模型消耗计入根预算，不能用重复委派绕过限制。
11. 最终结构化结果有 outcome、summary、call_id、必要 exit_code、错误和截断信息；有未结束子任务不能将父任务标为 succeeded。

出口：双 worker 协作可以恢复，失败和取消不启动依赖步骤。

## P6：UI 与完整端到端体验

交付物：机器列表、默认入口与独立会话、任务时间线、委派卡片、日志视图、取消与人工核对、快照/SSE 补放。

验收标准：

1. Main Agent 置顶；worker 在线状态与 idle/busy/blocked 分开展示，在线不误显示为可执行。
2. 委派卡片显示来源、目标、状态与结果，可打开子 session；追问进入当前会话，不猜测机器最近任务。
3. 执行期间追问排队，不修改活动 job；显示等待上线、排队位置和取消请求。
4. needs_attention 显示“需要核对”，不显示已完成；人工操作结果与数据库一致。
5. UI 取带游标快照后订阅 SSE，重复 event_id 不重复渲染，断线补放后无关键状态缺失。
6. 浏览器刷新/重连恢复已有任务；事件游标过期要求重取快照，日志过期/缺口/截断明确显示。
7. 中断模型草稿可识别，已提交消息和工具结果不重复；敏感历史与日志仅向认证用户开放。
8. 通过浏览器提交真实任务，观察工具和数据库事实，再在 UI 查看结果、取消与恢复，验证完整链路。

出口：无须查看开发日志即可理解任务处于何种状态、为何等待以及如何处置。

## P7：部署、运维与发布验收

交付物：Linux/macOS worker 二进制、systemd/launchd 配置、Caddy 配置、主节点安装/升级/备份说明、完整验收报告。

验收标准：

1. 两个平台从干净机器按文档安装，注册、执行、超时、取消和重启恢复通过。
2. 主节点常驻运行，WSS/SSE 经 Caddy 长连接可用；健康检查区分存活与调度就绪。
3. 在线备份和迁移可验证；升级不丢失未确认调用、去重水位和父子等待关系。
4. 恢复旧备份先停止自动调度并核对 worker 账本，不因主库缺少记录启动重复执行。
5. token 撤销、更新 token 后对账、数据目录锁、磁盘预算与日志保留在部署环境生效。
6. worker 无模型进程/密钥；主节点 runtime 无本地执行工具；所有公开入口通过认证。
7. 下列 Spec v2 对照表全部通过，故障场景不以普通 happy-path 演示代替。

出口：全量通过后发布 MVP。无需为了发布增加 spec 之外的新功能。

## 推荐开发任务颗粒度

每阶段拆成能独立评审的任务：Interface/数据迁移 → 正常路径 → 竞争与故障路径 → UI/运维入口 → 验收记录。状态机、协议变更与故障处理一起提交，避免先上线执行、随后才补安全语义。

每个任务说明引用阶段编号和验收条目，例如“P3-结果 ACK 丢失恢复”。验收发现的缺陷回到所属 Module 修复，不在 HTTP 或 UI 增加临时状态判断绕过生命周期。
