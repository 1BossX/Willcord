GET STARTED

部署中心，连接机器，开始任务。

Willcord 是产品名称，安装文件与命令沿用 WorkerPlane。
主节点提供 HTTPS 服务，worker 安装在执行机器的宿主机上。

默认流程：部署主节点 → 信任内部 CA → 安装 worker → 核对指纹批准 → 等待可执行 → 完成只读任务。一行安装只使用已发布的正式 Release；无正式版本时会退出。

01 / MAIN NODE

部署主节点

Linux 主节点先准备 Docker Compose v2，再运行向导输入访问地址、模型配置和管理员密码。向导启动服务并导出 ca.pem。

curl -fsSL https://1bossx.github.io/Willcord/install.sh | bash -s -- main

先让浏览器信任根证书，再安全复制给执行机器。

选择已发布版本并校验 SHA-256，Docker 镜像固定版本。若无适用产物，按指南从源码构建。

Docker 部署指南 ↗systemd 与运维手册 ↗
02 / WORKER

安装并授权机器

在控制台“机器授权 → 添加机器”复制命令。Linux/macOS 平台自动识别，下载文件校验后安装并申请加入。

curl -fsSL https://1bossx.github.io/Willcord/install.sh | bash -s -- worker --server 'https://plane.internal:8443' --ca '/absolute/ca.pem'

替换地址和执行机器上的 CA 路径。个人电脑使用普通账户；常驻服务器加 --system --user 'ops'，指定已有非 root 账户。控制台打开“机器授权”，核对节点 ID 和指纹后批准，等待机器显示“可执行”。

下载发布产物 ↗worker 安装与系统级服务 ↗
03 / FIRST TASK

创建会话，检查结果

在工作台选择可执行的机器和默认 workspace，创建独立会话。输入“列出当前工作目录的文件，并报告工作目录路径”，检查回复与任务时间线。

已有项目通过 workspace add 添加绝对目录，再创建新会话。跨机器协作使用 Main 会话，由主节点查看机器并委派任务。

升级前暂停调度、等待任务结束并备份。未知执行状态先人工核对。

完整安装与使用说明 ↗

Linux 用户级服务依赖 systemd 用户会话，macOS 用户级服务在登录后启动。需要开机启动时，使用系统级安装并指定非 root 执行账户。执行机器必须能访问主节点。

CURRENT SCOPE

清楚的能力，明确的前提。

执行机器必须能够访问主节点。隔离网段内需要可达的内网主节点，跨 NAT 中继尚未交付。

执行端可选择用户级或系统级服务。系统级安装需管理员权限，并以指定的非 root 账户执行；具体启动行为与权限需按安装方式验收。

项目仍处于开发与受控验收阶段，生产环境采用前应完成自身环境的安全、权限与故障恢复验收。安装后请先验证机器授权、工作目录权限和一次真实任务。
